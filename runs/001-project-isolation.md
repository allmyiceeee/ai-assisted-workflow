# Прогон 001: ограничение источников одним проектом

Дата: 2026-11-24. Среда: текущая сессия Codex, встроенные инструменты субагентов. Все данные синтетические.

## Задача и критерии

Добавить `check(root, response, expected_project=None)` и CLI-флаг `--project` для команды `check`. С указанным проектом все источники должны принадлежать ему после разрешения пути. Невалидный slug отклоняется. Без параметра сохраняется прежнее поведение. Существующие ограничения путей сохраняются.

Режим: ограниченная задача по изменению поведения кода — исполнитель и независимый ревьюер. Ведущий назначает файлы, запускает роли последовательно и передаёт замечания. Прямые API-вызовы не используются.

## Запуск исполнителя

- Инструмент: `collaboration.spawn_agent`.
- Идентификатор: `/root/implementer`.
- Явно запрошены: `gpt-6-luna`, reasoning `medium`, контекст `none`.
- Назначенные файлы: `tools/workbench.py`, `tests/test_workbench.py`.
- Переданы задача, критерии, команда проверки, запрет commit/push и требование не менять чужие файлы.
- Результат: добавлены параметр, флаг и проверки соответствия проекта, некорректного slug, обхода через `..` и CLI.
- Сообщение исполнителя: 13 тестов прошли. Ведущий независимо повторил запуск: 13 прошли.

## Первое независимое ревью

- Инструмент: `collaboration.spawn_agent`.
- Идентификатор: `/root/reviewer`.
- Явно запрошены: `gpt-6.2-astra`, reasoning `high`, контекст `none`.
- Переданы исходные критерии, расположение diff и запрет редактировать файлы. Ревьюер получил доступ к реальным изменениям, а не только пересказу исполнителя.
- Вердикт: `request_changes`.
- Все 13 тестов прошли, но ручная проверка обнаружила дефект: `python tools/workbench.py context demo-vault arena --project another` вернула код 0 и контекст arena. Флаг предназначен для check и не должен молча игнорироваться командой context.
- Требование исправления: отклонять такое сочетание до чтения базы и добавить регрессионный тест.

## Возврат замечаний

Ведущий вызвал `collaboration.followup_task` для того же `/root/implementer`, передал воспроизведение и критерий исправления. Максимум по политике — два раунда исправления; выдуманные замечания ради демонстрации запрещены.

Исполнитель добавил отказ до чтения источников и регрессионный CLI-тест. Сообщил о 14 проходящих тестах. Ведущий повторил проверку: все 14 прошли; TOML и JSON разбираются.

## Повторное ревью и итог

Ведущий повторно вызвал `/root/reviewer` через `collaboration.followup_task`. Ревьюер воспроизвёл прежнюю команду: теперь код завершения 1, содержимое заметок не выводится. Все 14 тестов и `git diff --check` прошли. Итоговый вердикт: `approve`, блокирующих замечаний нет.

Итог: одна реализация, два прохода независимого ревью, один раунд исправления. Ведущий не исправлял код за исполнителя. Человек принимает решение о дальнейшем использовании результата; одобрение агента не означает разрешения на деплой.

## Ограничения доказательства

Это составленная ведущим запись наблюдавшихся вызовов и ответов, не независимый экспорт телеметрии. Модели указаны как запрошенные параметры: сами субагенты не смогли подтвердить идентичность обслужившей их модели. Один прогон не доказывает сравнительное качество моделей или эффективность всех режимов. Конфиги ролей добавлены в ходе сессии, их автоматическая загрузка при новом открытии проекта не проверялась. В первом прогоне ведущий передавал параметры запуска непосредственно инструментам.
