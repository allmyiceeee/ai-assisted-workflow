# Запуск процесса в Codex

Открой этот репозиторий как рабочий проект. Скопируй запрос ниже и добавь задачу и критерии готовности. Доступные модели и права зависят от среды. Если роли не обнаружены, ведущий должен явно передать инструкции и модель при запуске субагента; молча подменять модель нельзя.

```text
Выполни задачу через субагентов по workflow/policy.json.
Ты ведущий. Сначала прочитай AGENTS.md и конфиги .codex/agents/.
Выбери режим по сложности и последствиям ошибки и объясни выбор.
Для обычной задачи явно запусти workflow-executor на gpt-6-luna,
затем workflow-reviewer на gpt-6.2-astra в отдельном контексте.
Передай ревьюеру исходную задачу, критерии, diff и результаты проверок.
Если есть обоснованные замечания, верни их тому же исполнителю,
после исправления повтори ревью. Не более двух раундов исправления.
Не меняй файлы исполнителя одновременно с ним.
Ревьюер не редактирует код. В случае недоступности модели остановись и сообщи.
Сохрани в runs/ отдельную запись: задача, фактически запрошенные модели,
идентификаторы агентов, результаты каждого этапа, ограничения и итог.
Не придумывай расходы, результаты тестов или замечания.
Не делай commit/push/deploy без отдельного поручения.

Задача: ...
Критерии готовности: ...
```

## Что здесь автоматизировано

Во время сессии ведущий сам вызывает исполнителя и ревьюера, получает ответы и решает, нужен ли цикл исправления. Запуски обслуживает Codex; собственного клиента LLM API нет. Конфиги задают роли, но сами по себе не запускают цикл. `policy.json` читается ведущим как инструкция, а не исполняется отдельной программой. Это оркестрация внутри агентной среды, не автономный сервер.

Контексты ролей разделены, файловая система в первом эксперименте общая. Поэтому исполнитель — единственный писатель кода, ревьюер проверяет после завершения изменения. Ограничение «не редактировать» задано инструкцией, а не отдельной файловой песочницей.

## Совместимость

Формат TOML взят из [официальной документации субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents). В первом прогоне модели передавались непосредственно при вызове инструмента запуска. Автоматическое обнаружение этих файлов в новой сессии отдельно не проверялось.
