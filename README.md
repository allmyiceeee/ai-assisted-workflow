# Agent KB Workbench

**Память проектов для coding-агента: контекст с источниками, явные границы доступа и проверка ответа перед передачей человеку.**

Демонстрационный проект на основе моего рабочего процесса ведения проектной базы знаний в Obsidian. Решает практическую проблему: при переключении между проектами приходится повторно объяснять агенту архитектуру, принятые решения и ограничения.

## Что сделано лично мной

В исходном рабочем процессе я сформулировал задачу, структуру базы и все требования к навыку: отделение рабочих заметок от личных, правила обращения с конфиденциальной информацией, сохранение источников и разделение фактов и предположений. Инструкции создавались с помощью coding-агента по моим требованиям.

В этом репозитории исходный подход оформлен как публичный демонстрационный стенд. Код и документация подготовлены с помощью AI. Все проекты и данные здесь вымышленные. Это не публикация корпоративной базы и не заявление о самостоятельном написании кода без AI.

## Быстрый старт

Нужен Python 3.10+, внешних зависимостей нет.

```sh
python tools/workbench.py context demo-vault arena
python tools/workbench.py check demo-vault examples/good-response.json
python -m unittest discover -s tests -v
```

Первая команда формирует пакет контекста. Вторая проверяет структурированный ответ: наличие источников, разрешённые пути, совпадение цитат с файлами и отсутствие некоторых распространённых признаков секретов. Проверка не доказывает истинность всех утверждений или безопасность произвольного текста.

## Как использовать с агентом

1. Открыть репозиторий в coding-агенте и прочитать `AGENTS.md` и `skills/project-memory/SKILL.md`.
2. Попросить: «Используй навык project-memory. Собери контекст arena из demo-vault. Верни JSON по examples/good-response.json».
3. Запустить `check` для сохранённого JSON. При ошибке вернуть замечания агенту и повторить проверку.
4. Проверить смысл и полноту ответа человеком.

Сам агент запускается в вашей среде. Python CLI не вызывает LLM, не управляет несколькими моделями и не обеспечивает их изоляцию. Оркестрация здесь — явный процесс передачи контекста, ответа и замечаний; автоматический multi-agent runtime не реализован.

## Состав

- `skills/project-memory/SKILL.md` — поведение агента при чтении и обновлении памяти.
- `AGENTS.md` — правила работы в демонстрационном репозитории.
- `tools/workbench.py` — упаковка контекста и детерминированная проверка ответа.
- `demo-vault/` — синтетическая база игрового проекта.
- `tests/` — проверки границ доступа и ошибочных ответов.
- `docs/design.md` — архитектурные решения, ограничения и дальнейшие эксперименты.

## Что измеряется

CLI показывает длительность собственной операции, число символов контекста и результат проверки. Это не latency модели и не расход токенов. Замеры качества LLM и стоимости API пока не проводились. Для них нужны реальные запуски, usage от провайдера и зафиксированные тарифы; будущие результаты нельзя заменять оценками «на глаз».
